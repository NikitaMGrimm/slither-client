# Appearance chooser preview

The default menu appends one passive Canvas after its existing appearance
buttons. Restore and successful selection/run/color edits copy the selected
bytes into the Rust `AppearancePreview` owner. Nickname edits, login bytes,
preference grammar and trusted Play admission keep their existing paths.
Factory callers can select `ownedAppearancePreview` with `ownedMenuUi`; leaving
the flag false preserves the menu-only composition.

Rust owns the selection ticket, supported route descriptor, fixed 320 by 128
projection and static display pose. It uses the existing curve sampler,
standard body planner, paired/single-image/mouth face layouts, ordinary antenna
preparation and browser submission helpers. There is no preview session, clock,
animation, random stream or JavaScript geometry/palette fallback.

The local route shares gameplay's Rust standard-source policy: it preserves the
requested built-in run palettes, counts and seam without modulo-three projection.
The candidate default bank has 42 distinct body families, seven ordinary shaded
variants and sixty variants for the represented cycle family. Food/prey use the
same expanded source-size plans in gameplay. The existing chooser exposes IDs
0 through 65; its storage and explicit Play routing are unchanged. The local
custom editor still offers indices 0, 1 and 2, which now name standard colors;
external admitted custom runs retain full normal palette IDs and first shading.
Built-ins 25/44/63/64 retain their ordinary paired-eye variants; other local faces
remain plain, with no antenna or face images and default body geometry. The
branded background is unchanged. The procedural material cutover is a separate
matching-Wasm/native visual acceptance gate, not an artwork-parity claim from
resolver or inert tests. The stock route uses the same
existing ready borrowed provider objects as gameplay, including represented face
families and ordinary
antennas. Stock preview requests `own: true` and cosmetic zero, borrowing the
already-selected, already-ready current-own static accessory through the same
trusted adapter. Explicit complete geometry is retained exactly; cached-entry
forward comes from the existing Rust `stock_accessory_forward` policy. Paired
and Mouth faces use the existing placement, crop, alpha and ordered submission.
A selected SingleImage remains unsupported; accepted custom runs determine face
eligibility first. Local preview keeps `own: false` and no accessory. No wire
cosmetic, preview ID or menu action selects an accessory, and no gameplay state
changes. No new catalog, loader or source artwork is supplied. Pending and
unsupported provider results hide the
old image and show a plain status. They do not start loading or automatic retry;
a later menu selection can request another projection.

Only the stock adapter's privately identified selected-accessory face rejection
becomes an unsupported preview. Its public throw contract stays unchanged for
other callers. Unrelated errors, forged status/message fields and falsy primaries
retain the existing failure path. The trusted load-once commitment and its
same-URL pre-event mutation limitation remain as documented in
[static accessories](static-accessory.md); the preview adds no readiness policy.

Selection is source-free. The captured microtask runs after the menu operation
unwinds, checks document/generation/topology and the current Rust ticket, and
skips stale or already-drawn tickets before opening a source lease. Rendering
uses that isolated per-operation lease and a separate captured Canvas frame.
Both the preview target and active world target are forbidden as selected
sources. No pixels are read. Source retention ends before copied status and
visibility reach the DOM. Cleanup attempts Canvas restoration, source release,
DOM removal and native free while preserving the first thrown value, including
`undefined`. Reentrant teardown defers native free until borrowed work unwinds.

Native tests cover copied revisions, chooser admission, the local resolver and
all 66 represented stock descriptors with bounded geometry. Inert Node tests
exercise actual menu/runtime/provider glue with labelled generated-ABI and
Canvas doubles. The additive real-Wasm smoke source checks both providers,
source identity, all represented stock selections, alias rejection and cleanup
when run against a fresh matching build. These are separate from real browser
Canvas execution, pixels, retained-reference comparison, complete look/feel,
installed host and official-server acceptance. No stock-pixel or full-goal
equivalence is claimed by this slice.
